# Support

## The short version

There isn't any.

## The slightly longer version

VERGIL is one person's lab, not a product. There's no support team,
no help desk, no SLA and no roadmap you can file a request against.
There's me, in the garage, building the race car I want, and
changing it whenever I feel like it.

If you're running VERGIL yourself and something broke: I admire your
courage, and I'm sorry, but you're on your own. It's MIT licensed and
the source is all there. Fork it and fix it the way you'd fix your
own car. That's what the license is for.

## What you can do

- **Learn from it.** The docs site explains how it all fits together,
  and the specs, plans and retrospectives in each repo show how it got
  that way. Start at the
  [VERGIL docs site](https://vergil-project.github.io/vergil-tooling/).
- **Argue with it.** If you think a design decision is wrong, make
  your case in
  [Discussions](https://github.com/orgs/vergil-project/discussions).
  I read it now and then. Don't expect a reply, and do expect spam to
  vanish.
- **Report a security problem.** That's the one thing that gets a
  real response. See the [security policy](SECURITY.md).

## What you can't do

Open an issue or a pull request and expect anything to happen to it,
other than its being closed. See
[CONTRIBUTING](CONTRIBUTING.md) for the longer explanation, with more
jokes.
